Why are messages IDs needed?
Message IDs are needed when dealing with undelivered messages.
The server will be able to tell a user that their message was not able to be delivered.
Regardless of the order that they came in.
This will also be helpful for resending, clients could ask other clients if they received a specific message.
If not, send it again.

Why didn't I consider them before?
I thought of TCP as asurring delivery, but I had forgotten that this is a networking program, not just communication inside my computer.
SO while TCP promises integrity, order, etc, it does not promise connectivity (for obvious reasons).
Message IDs are only really needed if connectivity is not stable.

Message IDs:
An ID is conformed of 2 things:
- 4 bytes of host
- 4 bytes of sequential counter.
8 bytes total.

So each host, can have 4294967296 messages.
